# Contributing

Keep changes focused and describe the problem they solve. Include a reproduction or a test for workflow bugs. Run `npm run check` before proposing a change.

Use fictional fixtures, keep production endpoints and credentials out of the repository, and distinguish working features from future plans. Comments should explain non-obvious decisions. Document material use of generation tools in a change description when relevant to review or funding provenance.

The current public-facing deliverable is a demonstrator. Discuss persistence, authentication and backend integration before expanding its scope.
